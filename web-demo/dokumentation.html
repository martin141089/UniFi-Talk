TalkAnchor

Deine dynamische IP im Griff.
Stay registered. Stay reachable.

Ein selbst gehosteter Wachdienst, der eine UniFi-Talk-Installation automatisch an ihrer aktuellen öffentlichen IP verankert — damit das Telefon auch nach dem nächsten Providerwechsel noch klingelt.

v0.2.3 MIT-Lizenz github.com/martin141089/UniFi-Talk

Das Problem

Eine vergessene Einstellung, ein stummes Telefon

UniFi Talk registriert sich bei deinem SIP-Trunk — bei den meisten deutschen Anschlüssen die Telekom — mit einer externen IP-Adresse, die fest in der Sofia-Profil-Konfiguration hinterlegt ist. Solange sich diese IP nicht ändert, bemerkt das niemand.

Hat dein Anschluss aber eine dynamische öffentliche IP — der Normalfall bei DSL- und Kabelanschlüssen in Deutschland — wechselt dieser Wert von Zeit zu Zeit: bei einer Zwangstrennung, einem Router-Neustart, einer DHCP-Lease-Erneuerung. UniFi Talk bekommt davon nichts mit. Die Registrierung beim Trunk schlägt fehl, Audio bricht ab, Anrufe werden getrennt.

Für ein Unternehmen, das auf erreichbare Telefone angewiesen ist — eine Ferienwohnung, ein Handwerksbetrieb — ist das kein kosmetisches Detail, sondern ein echtes Geschäftsrisiko.

Die UniFi-Talk-App bietet dafür keinen Schalter. Der Wert wird intern verwaltet und bei jedem App-Update kommentarlos zurückgesetzt — auch wenn er zuvor von Hand korrigiert wurde.

Wie TalkAnchor arbeitet

Ein Kreislauf, alle paar Minuten

TalkAnchor läuft als eigener, schlanker Dienst auf einem separaten Gerät im selben Netz — nicht auf dem UDM selbst, damit ein UniFi-Talk-App-Update es nicht mit löschen kann. Alle paar Minuten durchläuft es denselben vierstufigen Zyklus.

01 · PRÜFEN

Zwei Quellen befragen

Cloudflare-Tunnel-Connector-IP als primäre Quelle, ein konfigurierbarer HTTP-Echo-Dienst als Fallback — beide müssen übereinstimmen.

02 · VERGLEICHEN

Hat sich etwas geändert?

Abgleich gegen den zuletzt bestätigten, tatsächlich angewendeten Stand. Keine Änderung — kein Eingriff.

03 · ANWENDEN

Sicher schreiben

Backup anlegen, Sofia-Profil per SSH patchen, Trunk-Profil neu starten — alles über eine key-authentifizierte Verbindung.

04 · ABSICHERN

Health-Check & Rollback

Prüft, ob der Trunk sich wieder gesund registriert. Falls nicht: automatischer Rollback auf den letzten funktionierenden Stand.

Zwei Betriebswege

Läuft, wo es am wenigsten Aufwand macht

Eigenständig

Docker-Dienst

Für alle mit einem Raspberry Pi, NAS oder Mini-PC im Netzwerk. Ein Compose-Kommando, dann der interaktive CLI-Wizard.

  • docker compose up -d
  • Interaktiver Terminal-Wizard (talkanchor setup)
  • Dashboard unter http://<host>:8420
Home Assistant

Add-on

Für alle, die Home Assistant ohnehin schon betreiben und lieber über den Supervisor verwalten.

  • Installation über den Add-on-Store
  • Geführter Web-Wizard, kein Terminal nötig
  • Schreibt direkt in die Add-on-Optionen

Was mitkommt

Vorsichtig by Design

Zwei-Quellen-Abgleich

Erst wenn beide IP-Quellen übereinstimmen, passiert überhaupt etwas.

Dry-Run als Standard

Sieh genau, was TalkAnchor tun würde, bevor je eine SSH-Verbindung aufgebaut wird.

Backup vor jedem Schreiben

Zeitgestempelt, lokal und auf dem UDM, mit dokumentiertem Wiederherstellungsweg.

Health-Check + Rollback

Registrierung wird nach jeder Änderung geprüft; im Fehlfall automatische Rückkehr zum letzten guten Stand.

Rate-Limiting

Ein flatterndes IP-Signal wird protokolliert und zurückgestellt, nicht wiederholt scharf ausgeführt.

Austauschbare Benachrichtigungen

ntfy, generischer Webhook (Home Assistant, Discord, Slack) oder E-Mail.

Geführter Setup-Wizard

Als CLI oder gleichwertiger Web-Wizard — inklusive SSH-Discovery und Inline-Tests.

Lokales Dashboard

Aktuelle IP, Health-Status, Verlauf, Live-Log und manuelle Aktionen auf einen Blick.

Plugin-Architektur

UniFi Talk ist der Referenzadapter, nicht die einzige Möglichkeit.

Sicherheit zuerst

Kein Zauberwerk, nur Vorsicht

Nur SSH-Key-Authentifizierung. Es gibt kein Passwort-Feld — dieser Adapter kennt gar keine Passwort-Option.

Host-Key-Verifizierung. Unbekannte Hosts werden abgelehnt statt beim ersten Kontakt blind vertraut.

Backup vor jedem Schreibzugriff, lokal und auf dem Gerät selbst, zeitgestempelt.

Automatischer Rollback bei fehlgeschlagenem Health-Check — nie ein stillschweigend kaputter Zustand.

Rate-Limiting verhindert wiederholtes scharfes Schreiben bei instabiler Leitung.

Dry-Run ist der Standard. Nichts wird scharf geschaltet, bis du es zweimal explizit bestätigst.

Im Dashboard

Alles auf einen Blick

Aktuelle IP, Health-Status, Verlauf und manuelle Diagnose-Aktionen — dieselbe Ansicht, ob eigenständig betrieben oder als Home-Assistant-Add-on.

Schnellstart

In fünf Minuten startklar

Eigenständig

# Repository klonen
git clone https://github.com/martin141089/UniFi-Talk.git talkanchor
cd talkanchor

# Interaktiven Wizard starten
uv venv .venv && uv pip install -e . --python .venv/bin/python
.venv/bin/talkanchor setup

Home Assistant

# Settings → Add-ons → Add-on Store → ⋮ → Repositories
https://github.com/martin141089/UniFi-Talk

# Add-on installieren, starten,
# dann "Setup-Wizard öffnen" im Dashboard

Der Wizard schreibt zuerst immer dry_run: true und schaltet erst nach einer zweiten, expliziten Bestätigung scharf. Vollständige Referenz für jede Einstellung: CONFIGURATION.md.

Kein offizielles Ubiquiti-Produkt. TalkAnchor verändert eine von der UniFi-Talk-Anwendung verwaltete, nicht offiziell dokumentierte Konfigurationsdatei über SSH. Nutzung auf eigene Verantwortung — vor dem ersten produktiven Einsatz den Dry-Run-Modus nutzen und ein aktuelles Backup des UniFi-Systems vorhalten.
